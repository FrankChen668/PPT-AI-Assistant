# Lightweight SDD (Spec-Driven Development) — Public Guide

> 精简版 SDD，供公开仓库外部贡献者参考。Private Dev Repo 使用更完整的内部治理与变更控制文档；这些 Private-only 文档不进入 Public Snapshot。

## 核心循环

```
真实问题 → 分级 → 基线和范围 → 实施 → 测试 → 复核 → Draft PR → 合并或回滚
```

## 变更分级

| 级别 | 标准 | 要求 |
|------|------|------|
| 小改动 | 单文件、单函数、无接口变更、无风险 | PR 中记录目标、Changed Files/Diff 摘要、测试 |
| 普通 | 涉及多文件、接口、中等风险 | 填写 Change Spec、测试、复核 |
| 高风险 | 架构、核心链路、数据模型、安全、发布边界 | 完整 Change Spec、完整验收、明确回滚步骤、独立复核 |

拿不准时按更高一级处理。

## 开发约束

- **不重复造轮子**：先搜索确认“原来有没有”，再决定“是否新增”
- **不重复定义**：阶段名、状态值、路径、schema 字段、模型配置、质量门规则 —— 能复用现有定义不另写一套
- **不猜字段**：重要流程数据用稳定 schema/类型/校验，不用 fallback 链
- **规则落代码**：关键业务规则不只写在 prompt 里，必须落到代码、schema、校验或质量门
- **不吞错误**：失败必须能看出是模型调用、解析、schema、业务规则、渲染、导出还是质量门失败
- **不堆补丁**：重复出现的问题优先收紧 schema、职责边界、校验或现有入口
- **不滥用抽象**：只有能减少复杂度或强化边界时才允许新增管理器/引擎/Agent

## 交付自查清单

- [ ] 是否削弱现有校验？
- [ ] 是否绕开主链路？
- [ ] 是否重复造轮子？
- [ ] 是否降低可诊断性？
- [ ] 是否缺少必要测试？

## 阶段复盘

每完成一个大阶段，自查是否偏离主线：目标是否仍是真实用户价值、范围有没有悄悄扩张、有没有引入未经确认的新架构。发现偏离先停下校准，再继续。
